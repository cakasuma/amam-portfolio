# Architecture Decision Records

One record per decision that was not obvious at the time. An ADR captures the
context and the trade-off, so that a future reader can tell the difference
between a considered choice and an accident.

## Rules

- **Numbered sequentially**, `NNNN-kebab-title.md`.
- **Written once.** An accepted ADR is not edited to reflect new thinking. When
  a decision changes, write a new ADR and mark the old one `Superseded by
  ADR-NNNN`.
- **Record the trade-off**, not just the outcome. An ADR with no consequences
  section is a note, not a decision record.

An ADR answers *why is it like this?* For *what does it do?*, see
[`openspec/specs/`](../../openspec/specs/).
